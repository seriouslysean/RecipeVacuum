# Client notes

What WoW Forever's client does, where the addon depends on it. Measured in game on build 1.60.1.71037 unless a file is named. Blizzard's UI source for this client: [Gethe/wow-ui-source, `forever` branch](https://github.com/Gethe/wow-ui-source/tree/forever).

## Gamepad

With the Gamepad UI (Steam Deck), Blizzard's own code refuses to run on anything an addon wrote, so Recipe Vacuum writes nothing into Blizzard's frames, lists, menus or panels and opens none of its windows (owner decision; the same rule for every input method, not a gamepad mode). Measured in game on WoW Forever:

- `SmartNavigation.lua` `EnsureIsSecure` stops when it reads anything addon code wrote. After rows were inserted into the profession recipe list, the d-pad stopped moving (stack: `Navigate`, `SelectButton`, `EnsureIsSecure`).
- `ADDON_ACTION_FORBIDDEN` named Recipe Vacuum for `SetPreferredGamepadInteractTarget`.
- Opening the character window from the gamepad radial failed with "attempt to compare a secret number value (execution tainted by 'RecipeVacuum')".
- `OpenWorldMap` from addon code taints (TrainerSpells, pull request 9), and so do `MenuUtil.CreateContextMenu` and `Menu.ModifyMenu` entries. A map pin is `C_Map.SetUserWaypoint` plus `C_SuperTrack.SetSuperTrackedUserWaypoint(true)`, with nothing opened.
- Other addons that show recipes for unlearned professions (SkillUp Forever, TrainerSpells, Macro Assist) keep their own frames beside Blizzard's.

What is no longer done: unlearned rows in the recipe list, source marks on rows, the source line, item row and Show Map button in the recipe pane, the Recipe Vacuum section of the filter menu, the first-run help tip, and any call that refreshes Blizzard's list. Unlearned recipes will live in Recipe Vacuum's own panel beside the window, fed by `ns.GetUnlearnedRecipes`.

## Panel

Prototype seen on the Steam Deck (owner, 2026-11-26): the d-pad reaches the panel, scrolls to the bottom, nothing is blocked. `Panel.lua` anchors to `ProfessionsFrame.ProfessionsOverviewTab` (top right, 60 px up to the window's top), the first of the profession tabs in the right-hand column (Camelot `Blizzard_ProfessionsFrame.xml`; all tabs share one x). About 230 px are free right of that column at 1280x800 before the quest tracker; the panel is 270 wide and may overlap the tracker a little. The panel is a `PortraitFrameTemplate` (`Blizzard_SharedXML/Mainline/SharedUIPanelTemplates.xml:658`), as the window is (`Blizzard_ProfessionsFrameBase.xml:5`; owner, Deck, 2026-11-26: "a similar outline to the blizzard window, the alt color/texture headings and an icon on the top left"). The template's own API sets it up: `SetTitle` (`PortraitFrame.lua`, `TitledPanelMixin`) with the name and the version in a dim color escape (the title is one string), `SetTitleOffsets(nil, -5)` since the close button is hidden (`panel.CloseButton:Hide()`; the panel follows the window), and `SetPortraitToAsset` with the TOC's `IconTexture`, so the icon changes in one place. The list is a plain scroll frame (`ScrollFrameTemplate`, with Blizzard's `MinimalScrollBar`, the bar the recipe list uses, its thumb sized to the share in view and hidden while the list fits) with one own Button per row, as Field Guide Forever's list (`UI/List.lua`); SmartNavigation only calls `SetVerticalScroll` on a plain scroll frame. The list area is drawn as `ProfessionsRecipeListTemplate` draws its own: the atlas `Professions-background-summarylist` on a BACKGROUND texture with `setAllPoints` (`Blizzard_ProfessionsRecipeList.xml:10`) and an `InsetFrameTemplate` border (`:23-30`, the template's marble `Bg` hidden under the atlas). The list area sits 5 px in from the frame's left, right and bottom, as the window's list sits 5 px from its frame (`Blizzard_ProfessionsCrafting.xml:138-139`); width is 242 for the list (as before) + 8 left inset + 20 scroll bar column + 2 x 5 = 280 (`PANEL_WIDTH`). Content starts 40 px below the frame top (`CONTENT_TOP`: the window's own `RankBar` is at y -40, `Blizzard_ProfessionsCrafting.xml:199`; the top edge art is taller than the 21 px at which the background starts, `SharedUIPanelTemplates.xml:629`, and clipped a line placed there, owner, Deck, 2026-11-26): the discovery bar (below), then the list area, whose top is the top of the crafting page's own `RecipeList` (read when shown, 72 px below the window's top in `Blizzard_ProfessionsCrafting.xml:157`; owner, 2026-11-26: "Our header should match the height of the official layout"). There is no separate count line. The scroll bar column (20) is reserved only while the bar shows: the scroll frame's right edge and the child width follow the bar's OnShow and OnHide, so rows and headings use the full width when the list fits. Rows and headings sit as Blizzard's tree view places them (indent 10, `SkillUps` slot at -9, label 4 after it: 31 px from the heading's left edge). Loading: frames are made ahead (`POOL_ROWS`, `POOL_HEADINGS`) out of combat a few a frame once the panel exists; a build only fills existing frames in one pass, and the list is transparent until it is complete; when the client's names are still loading the first show waits up to 1 s (`WAIT_SECONDS`) instead of showing and redrawing. Unmeasured: the per-profession cost of one fill pass. The list area's bottom lines up with the crafting page's own list (owner, Deck, 2026-11-26), read from `ProfessionsFrame.CraftingPage.RecipeList` when the panel updates. The left inset (8), scroll bar column (20) and 5 below come from its `ScrollBox` anchors (`Blizzard_ProfessionsRecipeList.xml:61-66`). Tab column: the portrait corner stands 13 px outside the frame (`NineSliceLayouts.lua:20`) and the portrait is 62 px from 7 px above the top (`SharedUIPanelTemplates.xml:581-585`); the tabs begin 60 px below the window top, so the gap to the tab column is 2 + 13 and no corner covers a tab. The corner atlas size is not in the source, so the vertical overlap was not measured. A row's skill number fills the slot of Blizzard's skill-up arrow (26 x 15, 9 px left of the row) and the name starts 4 px after it. Unverified until the Deck: the pixel match, the title strip's fit, the discovery bar's width and look at 270, and the corner against the tabs.

What it follows, and why:

- Build cost. The prototype's first Deck run froze the profession window for about 6 s: 518 rows (every unlearned Blacksmithing recipe in the client, later expansions included) built three times in one second, because the crafting page's `Init` fires several times when the window opens, then again on a 1 s polling retry. Now every trigger only asks for a rebuild on the next frame (one build however many asks), rows are made in steps of at most 4 ms and 40 rows (`BUILD_BUDGET_MS`, `ROWS_PER_STEP`), the list is filtered before any row exists, and rows are kept across professions. The trace line "UI panel shown" and the `panel build` timing give the real cost. Expected, not yet measured on the Deck: under 100 rows, a few ms in total.
- Which recipes: the show rule and rank bands in `docs/data.md` ("Show rule", "Required skill"). The skill line is the page's `professionInfo.professionID`. Unverified in game: that this is the open expansion's child line on Forever, and that `skillLevel` and `maxSkillLevel` on the page's `professionInfo` are the character's skill and the rank's cap .
- Rank headings: found recipes are grouped by the rank band of their required skill (`docs/data.md`, "Show rule"), one heading per band that has recipes. Headings are `ProfessionsRecipeListCategoryTemplate` Buttons (`Blizzard_ProfessionsTemplates/Blizzard_ProfessionsRecipeList.xml:122`, a `ListHeaderVisualTemplate` from `Blizzard_SharedXML/ListTemplates.xml:22`): 25 high, `Game15Font_Shadow` title in `NORMAL_FONT_COLOR`, the plus or minus `CollapseButton` at the right. Text is the rank spell's subtext for the profession and step ("Journeyman", `C_Spell.GetSpellSubtext`, `ns.BandTitle`, `docs/data.md`, "Rank spells"; the spell's name is only the profession's), "Skill 76 to 150" when no rank spell is known, plus the found count while collapsed as a smaller dim "[n]" (`GameFontDisableSmall`, a second font string placed after the title's width; Blizzard's rows show their craftable count in brackets, `Blizzard_ProfessionsRecipeList.lua:228`). A click, or A on the gamepad, toggles it (our own `OnClick` in place of the list's, which toggles a ScrollBox node); open or closed is kept for the session only. The band holding the character's skill and the bands below start open. No menu or dropdown, which taint (Gamepad). The template's progress bar (`RankBar`) is hidden. Unverified on the Deck: A on a heading.
- Discovery bar: `ProfessionsRankBarTemplate` (`Blizzard_ProfessionsTemplates/Blizzard_ProfessionsRankBar.xml:5`), the template of the crafting page's `RankBar` (`Blizzard_ProfessionsCrafting.xml:197`), created with `CreateFrame` on the panel at its y (-40) and strata (HIGH, or it sits behind the panel's art). Same 18 px height. The template is 453 wide, so its Background, Border and Fill are set to the panel's inner width as its `overrideWidth` path does (`Blizzard_ProfessionsRankBar.lua:105-112`). Its `Update` is fed a table with found as `skillLevel` and total as `maxSkillLevel`, then the text is replaced with "%d / %d discovered" (`ns.GetListedRecipes`: found is the list ignoring search and filters, total every candidate of the skill line; `docs/data.md`, "Discovery"). `ownerManagesEvents` stops its own skill-line events, and its expansion dropdown is hidden. A plain frame with a mouse tooltip, so the gamepad cursor does not land on it. Unverified in game: the template's look at this width and that `Update` accepts the made-up table.
- Heading spacing: Blizzard's category holds a 1 px `topPadding` element above its recipes and a 10 px `bottomPadding` one below (`Blizzard_Professions.lua:960-974`; extents `Blizzard_ProfessionsRecipeList.lua:127-133`), each followed by the view's 1 px spacing, so an open category ends 12 px after its last row. The layout adds the same 1 and 10 for open bands; a collapsed band has no children, so none (the same as the window's tree).
- Details: a tap on a row (A or a click; the template's `SetSelected` shows its `Professions_Recipe_Active` look) selects it and opens details under the list, as `Blizzard_ProfessionsRecipeList.lua:46-62` selects. The selection stays until another row is tapped, the profession changes, or the recipe leaves the list (a filter or search); moving the cursor or hovering changes nothing but the tooltip, and a second tap does not close it (owner and coordinator, 2026-11-26). The details are an inset frame like the list's, sized to their content: the made item's `ProfessionsOutputButtonTemplate` (47 px, `Blizzard_ProfessionsTemplates.xml:282`, set up with `Professions.SetupOutputIconCommon`) with the name (`GameFontHighlightMed2`, 14 right of the icon) and "Requires Engineering (75)" (`ITEM_MIN_SKILL`, in `GameTooltipText` as the item tooltip draws it, `RED_FONT_COLOR` while the character's skill is below the requirement and `HIGHLIGHT_FONT_COLOR` once met; the screenshot of the item tooltip shows it red, owner, Deck, 2026-11-26) beside it, placed as `Blizzard_ProfessionsRecipeSchematicForm.xml:193-214`; the "Reagents:" label (`PROFESSIONS_REAGENT_CONTAINER_LABEL`) and, from `GetRecipeSchematic(recipeID, false).reagentSlotSchematics` (basic reagents only), one `ProfessionsButtonTemplate` icon (39 px) per reagent with "have/need name" (`TRADESKILL_REAGENT_COUNT`, `C_Item.GetItemCount`, red when short); then the sources. Sources with no place to pin are plain text lines. Every source with a place sits behind one `UIPanelButtonTemplate` labelled with the game's `SHOW_MAP` (used on the quest log's own Show Map button, `QuestMapFrame.xml:354`; owner, 2026-11-26: not one button per source). One place: the button pins it (`ns.ShowOnMap(target)`, `ns.SourceRows` in `RecipePanel.lua`) and its tooltip names the place. Several: pressing it opens, right under it, one own Button per place labelled "who, type" (tooltip: the place), sorted with `ns.SortTargets` (the player's zone first); picking one pins it and closes the list, and pressing Show Map again closes it. Opening is a press, never focus, so focus changes no layout; the details' height follows. The list is plain Buttons in the panel, so the d-pad path is list, Show Map, places, back. No Blizzard menu or dropdown (Gamepad). Portrait: the template's own (`SharedUIPanelTemplates.xml:581-585`, 62 px at -5, 7 from the frame's top left, ring corner 13 px outside, `NineSliceLayouts.lua:20`), nothing moved or clipped; the Professions window uses the same template and offsets. A source with no place to pin (a zone or world drop, a container) is a line of plain text. The list takes the height the details leave (`PlaceList`), keeps the selected row in view, and the d-pad reaches the buttons because they are real Buttons in the panel. A source's place is in the tooltip, not the label, to keep the button to one line at 270. Reagent rows are 43 px (Blizzard's slot is 50), so a recipe with many reagents makes tall details. Item names that were not loaded draw again on `GET_ITEM_INFO_RECEIVED`, registered only while one is missing. Unverified until the Deck: the template icons without a Blizzard parent, the button navigation from the list, the details' height with many reagents.
- Order and number: ascending required skill (`docs/data.md`, "Required skill"), then name; a recipe with no known requirement uses its `maxTrivialLevel`, the nearest threshold `TradeSkillRecipeInfo` (`TradeSkillUITypesDocumentation.lua`) gives. The row's number is that skill. The client has no field for the skill a recipe is learned at. Unverified: how closely the trivial level follows learn order.
- Row: `ProfessionsRecipeListRecipeTemplate` Buttons (`Blizzard_ProfessionsRecipeList.xml:134`), created by `CreateFrame` and filled directly (`Label`; the template needs no ScrollBox or data until `Init`, which is not called). 20 high with 1 px between rows (`Blizzard_ProfessionsRecipeList.lua:16-20`), headings 20 + 5 (`:108-132`), rows indented 10 under their heading, 5 px list padding. Font `GameFontHighlight_NoShadow` and the hover highlight (`Professions_Recipe_Hover`) are the template's. No icon, as Blizzard's list. The skill the list is ordered by sits at the row's left (`GameFontDisableSmall`, 22 wide, right-aligned; owner's request), the name after it, our source marks at the right. The name is white when the character's skill can learn it now and grey (`DISABLED_FONT_COLOR`) when the required skill is higher, or the recipe is `disabled` or locked by a specialization; it turns white under the cursor, as Blizzard's list does. No skill-up colors: a recipe not yet learned cannot be made, so it gives no skill (owner, Deck, 2026-11-26). The template's `OnEnter` and `OnLeave` are replaced by ours (theirs read a ScrollBox element); the heading keeps its own.
- Rebuild rule: the panel lays out its items and a signature of them (profession, search text, each band with its open state and count, and the recipe IDs of open bands in order). An equal signature changes nothing on screen but the text, colors and marks of the rows already there, which are refreshed in place, so a skill rise, a refreshed cache or the window's repeated list events never move a row under the gamepad cursor. The Deck log showed 22 rows rebuilt every 2 to 30 seconds with no input before this. The "UI panel shown" trace appears only when a rebuild happens. The scroll bar is the template's own and hides itself (`scrollBarHideable`) when the list fits. The title is the addon's name with the version after it in a dim color, "dev" in a working build.
- Filters, read from `C_TradeSkillUI` as `Blizzard_Professions.lua` reads them (`GetCurrentFilterSet`): the search box text (folded with `CaseAccentInsensitiveParse`; `HookScript` on the recipe list's `SearchBox` `OnTextChanged`), `GetOnlyShowSkillUpRecipes` (hides recipes whose `relativeDifficulty` is trivial; an unlearned recipe's `canSkillUp` is always false), `GetOnlyShowFirstCraftRecipes` (`firstCraft`). Not followed: "Have materials" (nothing unlearned is makeable) and "Show unlearned", which Forever turns off by default and which emptied the panel on the Deck (2026-11-26). Not applied: inventory slot, category and source filters, which have getters for the filter state but none that places a recipe in a slot or category. Refresh events: the page's `Init` (a filter change makes the client send `TRADE_SKILL_LIST_UPDATE`, which rebuilds the page), `TRADE_SKILL_LIST_UPDATE`, `TRADE_SKILL_DATA_SOURCE_CHANGED`, `NEW_RECIPE_LEARNED`, `SKILL_LINES_CHANGED`. One retry after 1 s when the client's names or factions were still loading.
- Tooltip: the game's own tooltip for the item the recipe makes (`GetRecipeSchematic`, `outputItemID`, `GameTooltip:SetItemByID`), or the recipe's spell when it makes none, so other addons' tooltip hooks (another addon) add their lines; our source lines follow. The row icon is `recipeInfo.icon`.
- Other windows: a post-hook on `UpdateUIPanelPositions` reads `GetUIPanel("center")`; the panel hides while another window holds it. Unverified on the Deck: whether Professions itself ever sits in the center slot (the code ignores that case).

To check on the Deck: d-pad reaches the panel and back, scrolls, no "Interface action failed" or `ADDON_ACTION_FORBIDDEN`, no stall when the window opens.

## Profession window

- The client leaves unlearned recipes out of `C_TradeSkillUI.GetFilteredRecipeIDs()` even with Show Unlearned on, so the addon works them out itself from `C_TradeSkillUI.GetAllRecipeIDs()`.
- Blizzard's source line (`RecipeSourceButton`) is never filled on this client, because `C_TradeSkillUI.GetRecipeSourceText` returns nothing.
- The client carries recipe categories nobody can be shown to have learned or found, such as fifteen Alchemy recipes under "Season of Discovery".

## Recipe items

- `C_Item.GetItemSpell` on a recipe item returns a generic "Learning" spell (402265), not the recipe.
- The item's tooltip data has an `ItemSpellTriggerLearn` line ("Use: Teaches you how to...") whose `spellID` is the recipe. Every loaded recipe item of every profession carries it, except items named Deprecated. The tooltip is only complete once the item's data is cached.
- Walking item IDs with `C_Item.GetItemInfoInstant` reads the client's own data and asks the server nothing: 342,000 IDs, 31,013 items, 2,974 of the Recipe class, in about 150 ms of work. Of those, 2,478 name a recipe, 253 teach nothing and 243 never answer a data request.

## Requirements

- The other faction's version of a recipe is marked only in the recipe's tooltip data: a `UsageRequirement` line of the `Faction` type.
- A specialization ("Requires Goblin Engineer") is a requirement of the item the recipe makes, not of the recipe. The recipe's tooltip shows it only once that item has loaded.
- That requirement line carries no ID for the specialization. Its fields on build 71037 (item 18984, Dimensional Ripper - Everlook): `leftText`, `requirementType` (Skill), `type` (UsageRequirement), `usable` (`false` when unmet).
- Whether a specialization has been picked is inferred, with no list of specializations: it is picked when the character meets a specialization requirement on any made item of the profession. Before that every such line is unmet and nothing locks. Not yet measured on build 71037: that a specialized character's own lines come back met (white), and which event fires on picking one; a lock can be stale after picking until the next skill change or reload.
- Row marks (owner's pick, 2026-11-24, from in-game previews of candidates): padlock `AdventureMapIcon-Lock`, trainer `Class` (book), vendor `Auctioneer` (coin stack), quest `Interface\GossipFrame\AvailableQuestIcon`, drop `lootroll-icon-need` (dice), unknown `common-search-magnifyingglass`. All exist on build 71037. Atlas marks keep the art's own shape, read from `C_Texture.GetAtlasInfo` (the padlock is 28 by 37). Sizes aim at the magnifier's visible height: measured from screenshots at about 1.16 UI scale, the magnifier drawn at 11 shows 13 pixels, the padlock at 13 showed 12, the quest mark at 16 shows 16, and the book and coin stack at 16 showed 14 to 15, so they are drawn at 14. The 14 for book, coin stack, dice and padlock is predicted from those measurements and not yet measured itself.
- A skill requirement with a rank ("Requires Engineering (300)", `ITEM_MIN_SKILL`) has a number in it; one without ("Requires Goblin Engineer", `ITEM_REQ_SKILL`) does not.
- A requirement the character meets is drawn white (`ffffffff`), one it does not is red (`ffff2020`). That red is not `RED_FONT_COLOR`.

## Trainers

- Trainers list recipes up to their own rank.
- `IsTradeskillTrainer()` is false for some NPCs that teach recipes (Westfall's Odd Child, six Alchemy recipes).
- `C_TradeSkillUI.GetTradeSkillLineForRecipe(spellID)` returns a profession line for recipes and for rank spells, and nothing for class spells. `C_TradeSkillUI.GetRecipeInfo` is non-nil for rank spells too.
- `GetTrainerServiceInfo` returns a category as its sixth value. Recipes have one ("Elixirs", "Camping"); ranks ("Journeyman Herbalism") have none. Blizzard's trainer window groups by the same value. `GetTrainerServiceStepIndex` marks only the next rank.
- The service list can arrive a moment after `TRAINER_SHOW`, and the window's filter hides known recipes.

## Loot, quests and vendors

- `GetLootSourceInfo(slot)` works. Field 6 of a Creature or GameObject GUID is its ID.
- Fishing: `IsFishingLoot()` is true and the source is the bobber object, so fishing finds are kept by zone.
- A container opened from bags reports an Item GUID; `C_Item.GetItemIDByGUID` gives its item ID.
- `LOOT_READY` can fire twice before `LOOT_OPENED`.
- A group roll (`START_LOOT_ROLL`) names the item but not what dropped it. Its loot handle is resolved by no documented function, and Blizzard's roll window shows no source either.
- Quest giver: `UnitGUID("questnpc")`. `GetQuestItemInfo` returns the item ID as its sixth value, before the name loads.
- A merchant row's details can arrive after the window opens.
- `UnitFactionGroup("npc")` reports "Alliance" for Alliance trainers and vendors. Neutral NPCs are not measured yet.

## Chat and names

- Forever writes player names in brackets ("[Name] says:") and has surnames; the full name with a space is a valid whisper target.
- The game's chat colors are in `ChatTypeInfo` and follow the player's settings.
- Whispers do not reach a Battle.net friend's character on another realm.
- Forever tags its own loot lines "[Loot]:" (`LOOT_ROLL_ALL_PASSED`).

## Places

- Subzones have IDs: `C_MapExplorationInfo.GetExploredAreaIDsAtPosition(mapID, position)` returned `{ 42 }` in Darkshire, and `C_Map.GetAreaInfo(42)` returned "Darkshire" (build 71091, 2026-11-25). ## Rank books

A rank book (Expert Fishing - The Bass and You, item 16083) is a recipe item whose item spell is the rank it teaches (`C_Item.GetItemSpell`: 19889, Expert Fishing; not the trainer-style rank spell, and `IsPlayerSpell` is the same check as `C_SpellBook.IsSpellKnown`, Blizzard_DeprecatedSpellBook/Deprecated_SpellBook.lua); its recipe subclass names the profession, and "Requires Fishing (125)" and "Already known" come as tooltip data (build 71091, 2026-11-25). The books are sold by a few vendors spread across the world, not by trainers (owner, 2026-11-25), so they are recorded as vendor sources like any recipe item. Primary profession ranks come from trainers instead: a trainer lists them as services with a spell and no category (Apprentice Alchemist 2259, Journeyman Alchemist 3101, Expert Alchemist 3464; build 71091, 2026-11-25), each shown once the one before it is learned. The addon keeps the step (docs/data.md, "Ranks"). Trainers have tiers, and a trainer lists ranks only up to the next one the character can learn: in Darnassus with Journeyman Alchemy, Milla Fairancora listed Apprentice only, Sylvanna Forestmoon up to Journeyman, Ainethil up to Expert (build 71091, 2026-11-25). So a trainer's top rank is learned only by visiting with the rank below it; Forever guides list Ainethil as an Artisan trainer (WoW-Professions, "WoW Forever Alchemy Trainer Locations"). Forever guides (Wowhead Forever profession overviews, Warcraft Tavern Forever trainer list; not yet checked in game) agree on the Expert book vendors above and add two more paths: Artisan Cooking, First Aid and Fishing come from quests (Triage for First Aid), and Forever adds manuals that teach a gathering profession without a trainer (Wowhead's Forever profession guides; Overgear, "WoW Forever professions changes").
